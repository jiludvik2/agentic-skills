## Open questions / follow-ups
- **s1-t1c HALT (autonomy-gate escalation, 2026-05-31):** schemathesis auth cannot map to `schemathesis run` faithfully. The bundle serialises `CaptureOutput.command` verbatim (`review_bundle.py:62`) and `schemathesis run` only takes auth on argv (`-H NAME:VALUE` / `-a USER:PASS`) — so a bearer token would land on the OS argv AND in the bundle the agent reads, violating the architecture's "tokens redacted from subprocess argv and stdout/stderr capture" contract + the passing security test. Options: **(1)** add a `redact=` layer to `run_and_capture`/`CaptureOutput` (scrub the token from `command`/stdout/stderr; simple+reusable, but token still transiently on live OS argv → ps-visible); **(2)** off-argv auth via a `SCHEMATHESIS_HOOKS` env-injection module (token never on argv — truest to the contract, but most complex, needs 4.0.10 verification); **(3)** defer schemathesis: carve it out of ADR-0020 (keep in-process under a documented exception / its own ADR), unblock s1-t2/s1-t3.
