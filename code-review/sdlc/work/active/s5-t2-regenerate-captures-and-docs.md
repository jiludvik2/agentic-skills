# Task s5-t2 — provisioned full-harness run: regenerate captures + reconcile docs

## Outcome

The migrated harness is proven end-to-end against the real toolchain: a full `run_smoke.py`
run exits 0 with all analyzers (including the two new precision coupling cases) producing
their expected signal; `results/raw/*.json` are regenerated to the bundle shape (resolving
the STATE carry-over that they are stale pre-ADR-0020 snapshots); the dated results report
is regenerated; and the QA README is reconciled to the bundle contract and the two new
fixtures. This is the carry-over resolution and the only task that needs the heavy
provisioned environment.

## Heavy-environment note (read first)

The full harness needs the provisioned toolchain (Node tools vendored via `scripts/setup.sh`
+ `npm install`, Trivy DB pre-fetched, `gitleaks`+`trivy` on PATH, `fastapi`/`uvicorn`),
runs **outside the sandbox** (network for the Trivy DB + the schemathesis HTTP loop), per the
QA README prerequisites. If that environment cannot be stood up in-session, this task's run
is **operator-driven** (the operator runs `run_smoke.py` and reports / commits the
regenerated captures) — the in-sandbox proofs (s5-t0 unit tests, s5-t1 pydeps integration)
remain green regardless. Flag via the autonomy-gate escalation interface if provisioning is
blocked; do not fake captures.

## Files to add / change

1. **`results/raw/*.json`** — regenerated by a full `run_smoke.py` run. Each file is now a
   single-tool `review-bundle.v1.json` (the CLI's `--analyzer X --output` shape), replacing
   the old consolidated snapshots. The two new coupling cases add `pydeps.json` /
   `depcruiser.json` content reflecting the precise planted defects.
2. **`results/<date>-results.md`** — the regenerated run record (14+ rows, ✅/❌ per analyzer).
3. **`README.md`** (`qa-analyzer-coverage` runbook) — reconcile to the bundle:
   - **Layout** block: `results/raw/<analyzer>.json` is now a *raw bundle* (per-tool raw
     stdout/stderr/exit/status), not "consolidated output"; add `bundle_oracle.py` to the
     layout with a one-line description.
   - **Analyzer → fixture map**: update the "Signal asserted" column to reflect raw-output
     oracles (not "SARIF finding"/"metrics"); **add two rows** — `pydeps` (labelled
     `a→b→a` cycle; "back-edge present in dep graph") and `depcruiser` `__mocks__`
     (prod→`__mocks__` edge; "edge into `__mocks__/` from non-mock source"). Note the
     existing `depcruiser` circular row stays.
   - Bump `updated:`/`verified-on:` frontmatter to the run date.
4. **`FINDINGS.md`** — only if the provisioned run surfaces something curated-worthy (a tool
   that silently degraded, a resolution quirk). Skip if nothing new — do not write filler.

- A full `run_smoke.py` run **exits 0**: all analyzers (12 existing + 2 new coupling)
  produce their expected signal against the real binaries. *(If the environment is

  heavy-environment note; record the run outcome in the close notes.)*
- `results/raw/*.json` are valid `review-bundle.v1.json` documents (schema-conformant:
  `schema`/`request`/`outputs[]` with `tool`/`status`/`exit_code`/`stdout`/`stderr`), not the
  old consolidated shape. The pydeps + depcruiser captures contain the planted coupling
  defects.
- README reflects the bundle contract, the `bundle_oracle.py` module, and the two new
  analyzer→fixture rows; frontmatter dates bumped.
- If any s5-t0 extractor was authored to a documented-but-unconfirmed native shape (e.g.
  knip/jscpd/schemathesis JSON) and the real capture differs, the extractor is tightened to
  the real shape and the s5-t0 unit snippet updated to match (keep the unit test honest).
