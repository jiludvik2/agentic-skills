# Task s2-t2 — golden-bundle fixture + edge-case hardening

## Outcome

A recorded **golden bundle** fixture pins the bundle's serialization contract end-to-end:
the CLI, run over recorded per-tool raw outputs, emits a bundle byte-equal to the committed
fixture (a regression guard against accidental serialization/schema drift). Edge cases that
the synthetic-capture tests don't exercise are covered.

## Context

s1's bundle tests construct synthetic `CaptureOutput`s and validate **structure** against
`review-bundle.v1.json`. They do not pin a realistic full-run bundle, so a change that alters
field ordering, status serialisation, or the request echo could pass structure validation
while silently changing the agent's contract. The bundle is deterministic by design
(`sort_keys`, sorted languages) — which is exactly what makes a byte-equal golden assertion
both feasible and valuable. Operator decision 2026-05-31: **recorded fixture + regression
guard** (not edge-case tests only).

## Design

- **Golden fixture** `tests/fixtures/golden_review_bundle.json` — a realistic bundle spanning:
  - all three output formats: JSON (e.g. bandit/radon), SARIF (e.g. semgrep/trivy), plain text
    (e.g. vulture/gitleaks);
  - all four ADR-0019 statuses: `ok`, `error`, `timeout`, `unavailable`;
  - a representative `request` echo (a diff-scoped, multi-language request).
  Generated by serialising a fixed set of recorded `CaptureOutput`s through `bundle_to_json`
  (so the fixture is reproducible from the same inputs, not hand-edited).
- **Regression-guard test** — build a `ReviewBundle` from the same recorded inputs (or invoke
  the CLI with adapters mocked to return them) and assert the emitted JSON is **byte-equal** to
  the committed fixture; also `jsonschema.validate` it against `review-bundle.v1.json`. A
  helper/`--update-golden` affordance (or a documented regen one-liner) keeps the fixture
  maintainable when the contract changes intentionally.
- **Edge-case coverage** (extend `test_review_bundle.py` / `test_cli_bundle.py`):
  - all-`unavailable` run → process exit code **0** (nothing errored — distinct from the
    existing error/timeout→non-zero tests);
  - non-UTF8 / control-character stdout round-trips **verbatim** through the bundle (extends
    the existing `test_raw_stdout_roundtrips`; add bytes that force escaping);
  - an **empty** `outputs` array (no analyzer selected) still produces a schema-valid bundle.

## Acceptance criteria

- `tests/fixtures/golden_review_bundle.json` exists, validates against
  `review-bundle.v1.json`, and contains at least one capture of each of the four statuses and
  each of the three output-format families.
- The regression-guard test asserts the emitted bundle is byte-equal to the golden fixture;
  the fixture is regenerable from its recorded inputs (no hand-editing required).
- Edge cases pass: all-`unavailable`→exit 0; non-UTF8 stdout round-trips verbatim; empty
  `outputs` validates.
- `uv run pytest`, `uv run ruff check .`, `uv run mypy code_review` clean.

## Test specification (write first, confirm RED)

1. `tests/test_review_bundle.py::test_golden_bundle_byte_equal` — recorded inputs →
   `bundle_to_json` == fixture bytes; RED until the fixture is committed.
2. `tests/test_cli_bundle.py::test_all_unavailable_run_exits_zero` — adapters mocked to return
   `unavailable` captures; CLI exits 0; bundle validates. RED if the exit-code logic ever
   treats `unavailable` as a failure.
3. `tests/test_review_bundle.py::test_raw_stdout_roundtrips_non_utf8` — stdout with control
   chars / non-ASCII round-trips byte-for-byte.
4. `tests/test_review_bundle.py::test_empty_outputs_bundle_valid` — a bundle with `outputs == ()`
   schema-validates.

## Notes

- Guard-rail (ADR-0020): this task adds **fixtures and assertions only** — no interpretation,
  ranking, or scoring code enters `code_review/`. The golden fixture records raw captures, not
  parsed findings.
- Keep the fixture small and deterministic — trimmed real tool output is fine, but it must
  serialise identically every run (sorted keys; no timestamps in the recorded captures, or
  pin `duration_s` to a fixed value in the recorded inputs).
